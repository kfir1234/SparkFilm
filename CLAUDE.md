# SPARK — AI-Produced Animated Feature

Feature-length (~90 min) English-language animated film, released on YouTube as ~9 episodes of ~10 min.
Written by Kfir Andre Sasson with Claude's help; produced with a mostly-local AI pipeline.

- Story source: [script/Spark-premise.pdf](script/Spark-premise.pdf) (2014 premise, the canon starting point)
- Production source: [production/high-level-production-plan.pdf](production/high-level-production-plan.pdf) (Hebrew, Nov 2026)

## Locked creative decisions

- **Genre:** emotional drama (a father seeking his family) with a sci-fi/metaphysical twist.
- **The spiritual dimension is shown on screen.** It is a real story location with its own visual language
  (`bible/locations/spiritual-dimension.md`, `bible/style.md`), distinct from both human universes.
- **Setting:** present day, United States. No real brands or companies (fictional stand-ins for IBM, Candy Crush, etc.).
- **The premise is a skeleton.** The full script adds subplots and develops supporting characters
  (co-founder/roommate, Jennie's father, the medium's arc, and others) to sustain 9 episode hooks.
- **Undecided until the full script exists** (don't resolve them on your own; track them in `story/open-questions.md`):
  the nature of the final crash (accident vs. choice vs. ambiguous), the medium's arc, and the ending's details.

## Current increment

1. **Pilot test scene** (~30 s, dialogue + some movement) to run the whole pipeline end to end.
2. Then **Episode 1 from the beginning**.
3. Before Episode 1: brainstorming sessions on structure (synopsis, 9-episode beat sheet, subplots, mythology).

## This is a film project, not a software project

The global software rules (TDD, 80% coverage, code-reviewer agents, API/security checklists) apply **only**
to helper code under `tools/`. They do not apply to screenplay, bible, or production documents.

## Working model: agile, episode by episode

The author writes the script in increments (an episode or a block of scenes), produces it, learns from it,
then continues. Consequences:

1. **Never write ahead of the current increment** unless asked. Propose; don't sprawl.
2. **Canon lives in files, not in chat.** Anything decided about story, characters, or style goes into
   `story/` or `bible/` in the same session it is decided.
3. **Produced scenes are locked.** Once an episode's animatic is locked (`status: locked` in its shot list),
   don't edit its scenes silently. Propose changes, and flag what has to be regenerated.
4. **Rule from the plan: no final video before that episode's animatic is locked.**

## Fountain conventions

- **One file per episode:** `script/episodes/epNN.fountain`. Each has its own title page
  (`Title: SPARK`, `Episode: N — <Title>`, `Credit`, `Author`, `Draft date`), and its body starts with
  `# EPISODE N — <Title>`. Group scenes under `## ` sequence headers when helpful.
- When working on an episode, read and edit **only that episode's file**. Locked episodes are read-only unless the author says otherwise.
- The full film (`script/spark-full.fountain`) is built by a script in `tools/` that concatenates the episodes
  (Fountain has no standard include). Regenerate it for full read-throughs or PDF export; never edit it directly.
- Every scene heading is **forced-numbered** so the shot list can reference it:
  `INT. MIKE'S CAR - DAY #E01-003#`
- Use a `= synopsis` line under each scene (one sentence, the scene's dramatic purpose).
- Use `[[notes]]` for production notes (route hints, VFX, open questions). Never put notes in action lines.
- Use `/* ... */` boneyard for cut material instead of deleting it.
- Character names in CAPS on first appearance in action; dialogue cues always the same spelling
  (`MIKE`, `KATIE`, `JENNIE`, `LUCY`, `JOE`, `THE MEDIUM` ...). Use `(V.O.)` / `(O.S.)` / `(CONT'D)` correctly.
- Mark the two universes clearly in scene headings or synopses: **Universe A** (IBM-life, Katie + kids)
  and **Universe B** (startup-CEO life, Jennie). A third world appears in the finale.
- Write for animation and AI generation: **visual, concrete action lines**; short shots; avoid long
  unbroken camera moves, crowds, and fine hand interactions unless the scene needs them.
- Target ~1 page ≈ 1 minute; each episode ≈ 10 pages and ends on a hook.

## Writing collaboration rules

- The author owns the voice. Claude drafts, offers options, and critiques. It does not overwrite approved text.
- **NEVER write into a script file (`script/**/*.fountain`) without the author's explicit approval of that text.**
  Brainstorm, propose drafts and options **in the chat only**. Write to the file only after the author says to.
- **Default loop, scene by scene:** the author gives the beats → brainstorm and draft options in the chat → the author
  decides and approves → Claude writes the approved text to the Fountain file → Claude records what changed in `story/`
  or `bible/` (new facts, new characters, continuity).
- Learn from the author's edits: if they keep rewriting a pattern (dialogue rhythm, action-line style), adapt future drafts.
- When drafting, offer **2–3 options** for key beats or lines and explain the trade-off in one line each.
- Keep the core motif intact: the ritual *"Do you know how much I love you?" / "Like the sun loves the sky." /
  "Always always."* It is the film's emotional spine and is mirrored in the ending.
- Check every new scene against `story/mythology.md` and the character files for continuity.
- Treat death, grief, and the "should Mike die to return" dilemma with care (also matters for YouTube policy).
- Avoid real brands and trademarks in the final script (e.g. IBM, Candy Crush). Use fictional stand-ins.

## Script → production handoff

After an episode is approved, break it down into `production/shotlists/epNN.csv`. Columns (from the plan):

| column | notes |
|---|---|
| `shot_id` | `E01-S003-SH010` (episode-scene-shot) |
| `episode`, `scene` | scene number matches the Fountain forced number |
| `characters`, `location`, `props` | names match `bible/` filenames |
| `framing` | ECU / CU / MCU / MS / WS / EWS, plus angle and movement |
| `dialogue` | the line(s) spoken in the shot |
| `duration_s` | estimate; average ~5 s |
| `route` | `dialogue` (InfiniteTalk) · `performance` (Wan-Animate-2) · `multi-char` (LTX-2.5 + IC-LoRA) · `motion` (Wan 2.2 I2V, first/last frame) · `hero` (paid: Veo/Kling, ≤ ~10%) · `blender-layout` flag for recurring locations or complex camera |
| `status` | `planned → keyframe → generated → qc-pass → final` (or `retry`) |
| `notes` | |

Targets: ~120 shots per episode and ~1,100 total. Use the `hero` route only after 2–3 failed local attempts.

## Production constraints (from the plan)

- Hardware: **RTX 5080 16 GB VRAM, 64 GB RAM**. Draft resolution and short clips locally; rely on offloading and
  BlockSwap. Rent GPUs (RunPod H100/5090) only for video-LoRA training.
- Budget route: **B (local + light cloud)**, about $200–$500 for the whole film.
- Style: stylized 3D (2D is the fallback). Both get tested in the pilot, then locked for all 9 episodes.
- Order per episode: script → shot list → bible updates → **voice recorded first** → animatic (FLUX.2 klein 4B
  stills in Resolve) → Blender layout (only if needed) → keyframes → video → QC against the bible → post.

### License guardrails (monetized YouTube = commercial use)

- OK: Wan 2.2, Wan-Animate-2, Qwen-Image(-Edit), FLUX.2 **klein 4B**, Z-Image, SeedVR2, RIFE, Chatterbox,
  RVC/Seed-VC, ACE-Step, LTX-2.5 (free under $10M revenue), ElevenLabs on a **paid** plan only.
- **Do not suggest:** FLUX.2 dev, FLUX.2 klein 9B, IndexTTS-2, or a local MiniMax H3.
- Label synthetic content on upload where it looks realistic. Give each episode a unique title and thumbnail.
